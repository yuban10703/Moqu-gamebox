# A06 · 验收记录模板

状态：**模板**。性能门槛在拿到真机基线后填写；发布前不得仍为空。

记录原则：
- 每个平台/设备组合单独一份记录；
- 只记录**实际操作过**的结论，未测写「未测」；
- 桌面截图、模拟器通过不算完成（对应规划阶段 B/F 的完成条件）。

## 1. 动作正确率（F01 / F02）

| 项目 | 方法 | 期望 | 实测 |
|---|---|---|---|
| 规则一致性 | 同一动作序列在 Web 与 APK 各执行一遍，比对最终局面与步数 | 完全一致 |  |
| 连续输入 | 每款游戏执行 ≥100 个有效动作（含快速连点、重复点击、撤销） | 无漏算、无重复执行 |  |
| 非法输入 | 故意撞墙 / 推向墙 | 有明确文字提示，计数不变 |  |
| 关卡可解 | 逐关走通（本机已用 A\* 求解器与见证解法双重校验） | 全部可解 |  |

## 2. 生命周期与故障（F03）

| 项目 | 方法 | 期望 | 实测 |
|---|---|---|---|
| 锁屏 / 后台回收 | ≥20 组「暂停 → 锁屏 → 唤醒 → 继续」 | 局面与步数完整保留 |  |
| 进程被杀 | 走几步后杀掉进程再进入 | 恢复到最后一次明确提交成功的局面 |  |
| 保存失败 | 观察写入失败时是否有可见提示 | 有提示 + 可重试 + 可导出 |  |
| 备份往返 | Web 导出 → Android 导入；反向再来一次 | 进度一致，冲突有提示 |  |
| 升级中断 | 覆盖安装新版本 | 已完成进度保留 |  |

| 残影 | 连续 100 步后观察棋盘 | 记录程度；需要时整屏全刷 |  |
