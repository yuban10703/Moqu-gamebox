## 关键流程

**继续游戏**：首页 → 读取存档元信息 → 显示关卡与步数 → 进入游戏界面（局面由存档状态还原）。

**开始新游戏（已有进度）**：详情页 → 点「开始新游戏」→ **弹确认**（明确说明替换且不可恢复）→
确认后删除旧存档 → 进入新局。**损坏存档同样需要确认**，避免静默删除。

**保存失败**：游戏界面显示「保存失败：原因」+ 重试 + 导出备份；重试是显式的「以本机进度覆盖」。

**存档损坏**：首页出现警告区块 → 点进入游戏界面 → 显示损坏提示 + 导出备份 + 重新开始（需确认）；
**原文件保持不动**，不会被自动写回覆盖。

**返回**：顶栏返回 → 浏览器历史回退；Android 系统返回键由网页层接管
（`window.__einkHandleBack`），在首页返回 `false` 时才退出应用。

**暂停**：暂停即落盘；暂停期间不接受任何输入；返回游戏界面时恢复。

## 数独交互预验证（M1 阶段 B06 项；**已完成** —— 数独已实现、已上真机，见 verification.md）

10.3 吋屏上 9×9 棋盘的舒适点击区存在风险，因此先用静态样例验证，再进入 M3 实现：

1. 用棋盘区宽度 1089 CSS px 粗算：`cell = floor(1089 / 9) = 121 px`（未扣两侧 5px 外框；按 `computeBoardLayout` 实为 **119px**）—— 直接点击可行；
2. 6 吋屏（宽 718 CSS px）粗算：`cell = floor(686 / 9) = 76 px`（实为 **74px**）—— 仍高于 48 px 门槛；
3. 但**候选数（笔记）**在 76 px 格子里显示 9 个小数字会不可读，因此实现时提供：
   聚焦格（选中格放大到独立区域）+ 独立大号数字区（0-9 按钮）+ 候选数在聚焦区放大显示；
4. 真机验证要点：右键「自动换行」与「聚焦格 + 数字区」两条路径都能完整解题；
5. 若 10.3 吋直接点击路径实测不佳，按规划只调整**呈现层**，规则与状态层不动。

（上述计算来自 `packages/core/src/layout.ts` 的纯函数，已由布局不变量测试覆盖；
真机实测值请填写到 [A01](A01-device-baseline.md)。）
