# A05 · 支持与分发范围

状态：建议方案（真机基线已采集，见 [A01](A01-device-baseline.md)；分发渠道仍需你定）。

## 支持的平台下限

| 平台 | 下限 | 依据 |
|---|---|---|
| Android APK | `minSdk 23`（Android 6.0） | BOOX 老机型（Note/Nova 早期固件）为 Android 6；WebView 语法按 **chrome110 基线**构建（`apps/web/vite.config.ts`；chrome69 的老降级方案已放弃，实测目标机 WebView 是 Chrome/146） |
| Android 目标 | `targetSdk 35` | 覆盖较新固件；未使用任何受限 API（无网络权限、无存储权限） |
| Web | chrome110 / Safari 16 级别的现代浏览器（构建目标见 `apps/web/vite.config.ts`） | Service Worker 仅作渐进增强，不可用时仍可游玩（只是不能离线冷启动） |

不支持低于 Android 6.0 的设备；不支持无触摸输入的设备（主操作是可见按钮）。

## Web 发布方式（建议）

- 产物是**相对路径**的静态文件（`apps/web/dist`），可放任意静态托管（对象存储 / Nginx / GitHub Pages / 内网服务器）；
- 不需要任何后端；也没有任何出网请求（游戏逻辑全在本地）；
- 若部署在子路径，无需改配置（`base: './'`）；
- 更新方式：整体替换 `dist` 目录即可；Service Worker 会因缓存名变化而更新，
  并且**不会在进行中的游戏里强制刷新页面**。

## APK 分发方式（建议）

| 阶段 | 渠道 | 说明 |
|---|---|---|
| 现在 | 本地侧载（`adb install`） | debug 签名，仅供你自己与内测用户 |
| 内测（G01） | 直接发 APK 文件 | 需要一份安装说明（离线、权限、备份） |
| 正式（G04） | 待定 | 需要生成正式 keystore 并配置 `signingConfigs`；若上架应用商店，需按当时要求准备隐私说明与目标 API |

正式签名注意：keystore 一旦用于发布就不能更换；升级必须用同一签名，否则用户数据会因签名不一致而无法覆盖安装。

## 备份与迁移承诺

- 备份文件（`BackupFileV1`）是**跨端通用**的 JSON，Web ↔ Android 双向可导入；
- 导入时对每款游戏给出冲突处理（默认「两者都保留」：先存一份备份副本，再写入导入的进度）；
- 备份里包含设备基线，便于事后定位「哪台设备上的哪一版」。
